Generate and redline contracts in a track-changes workspace, or chat with an 11,266-chunk M&A corpus — powered by Cohere embeddings, Neon pgvector, and Vertex Gemini 2.5 Flash on a corrective RAG pipeline.

Architecture

Corrective RAG pipeline

User query / draft / prompt
          │
          ▼
  Flash-Lite Anonymizer         ← PROCESS: replace entities with placeholders
          │  anonymized text          (PARTY_A, ORG_001, ...). Server-side, in-memory only.
          ▼
  Cohere Embed v4 (1024-d)      ← PROCESS: embed anonymized query
          │  query vector
          ▼
  ╔========================╗
  ║ Neon pgvector          ║  DATA LAYER: 11,266 corpus chunks
  ║ (IVFFlat index)         ║  (22 playbook + 7,067 CUAD + 4,177 MAUD)
  ║ cosine → top-12        ║  PROCESS: nearest-neighbor retrieval
  ╚========================╝
          │ top-12 + (optional) session context ↓
          │
          │        ╔==============================╗
          │ ←−− ║ Supermemory kind=context    ║  DATA LAYER: per-session
          │        ║ (read; skipped if empty)     ║  uploaded docs (NotebookLM-style)
          │        ╚==============================╝
          ▼
  Cohere Rerank 3.5             ← PROCESS: cross-encoder re-scoring  [Hub only]
          │  reranked context
          ▼
  Vertex Gemini 2.5 Flash      ← PROCESS: generate
          │                              Hub  → structured JSON, ≤14 issues + drafts
          │                              Chat → streamed prose + [n] citations
   ┌──────────┴────────────────────────└
   │                                   │
   ▼  Drafting & Review Hub          ▼  Ask the Corpus
  Editing Hub                          Stream answer
   PROCESS: per-change accept              PROCESS: SSE token stream
   reject / inline rewrite                 │  + rehydrate placeholders
   │                                   │
   ▼ bake                              ▼
  redline.docx · clean.docx               ╔================================╗
  memo.docx · register.json               ║ Supermemory kind=            ║
   │                                   ║ chat_exchange (write)        ║
   ▼                                   ╚================================╝
  ╔================================╗
  ║ Supermemory kind=            ║
  ║ review_summary (write)        ║
  ╚================================╝

  ↳ PII firewall regex re-screens every Supermemory write (second defense layer)
  ↳ Anonymizer rehydrates entity names on the way back to the user
  ↳ Per-session 24h TTL on all Supermemory data (server-side account setting)

Both surfaces (Drafting & Review Hub and Ask the Corpus) share the first five stages. The Hub branches into per-clause edit controls and four downloadable artifacts; the Chat surface streams the answer back and persists the anonymized Q&A. PII is anonymized server-side before any LLM or vector-store call, and a second regex PII firewall gates every Supermemory write.
